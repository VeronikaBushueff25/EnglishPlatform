## Этап 2. Аккаунты

Сделано (бэкенд):
- Identity: регистрация, вход, выход, сброс пароля, JWT 15 минут, refresh-токен в httpOnly cookie с ротацией
  и отзывом всех сессий при повторном использовании, блокировка после 5 ошибок входа, лимит запросов по IP.
- Роли `user` и `admin`, первый администратор из `Identity:AdminEmail` / `Identity:AdminPassword`.
- Админка: `GET /admin/users`, `PUT /admin/users/{id}/role`.
- Users: профиль `GET/PUT /me`, настройки `PUT /me/settings` (язык, цели, дневная нагрузка, часовой пояс, тариф Free).
  Профиль создаётся по событию `UserRegistered`, при отсутствии — при первом обращении.
- Миграции `Initial` для схем `identity` и `users`.
- Unit-тесты Identity и Users; интеграционный сценарий регистрация → профиль → refresh → logout.
- Интеграционные тесты пройдены на локальном PostgreSQL 16 (24.11.2026, все 56 тестов решения).
- Миграции и начальные данные выполняются под advisory lock PostgreSQL (`DatabaseSetupLock`):
  при одновременном старте нескольких экземпляров на пустой базе падало создание ролей (RoleNameIndex).

Сделано (фронтенд, 24.11.2026):

- `core/auth`: сессия в памяти (access-токен не хранится в localStorage), восстановление по refresh-cookie
  при старте, interceptor с токеном, заблаговременным refresh и одним общим refresh на параллельные 401,
  guard'ы `authGuard`, `guestGuard`, `adminGuard`. Ошибки API показываются текстом из ProblemDetails.
- Клиент API перегенерирован (`npm run api:generate`). Unit-тесты фронтенда: 22.
- Интерфейс переведён на Tailwind CSS 4 + spartan/ui (решение 6 в decisions.md): светлая и тёмная тема,

## Этап 3. Словарь

Сделано (24.11.2026):
- Модуль Vocabulary, схема `vocabulary`: `lexemes` (общая база: слово, фраза, идиома, фразовый глагол; часть речи,
  транскрипция IPA, уровень CEFR, ссылка на аудио, переводы и примеры в jsonb, категории массивом uuid[]),
  `categories`, `user_words` (личный словарь). Миграция `Initial`.
- Слово в личном словаре — своя копия: пользователь может править перевод, слово остаётся, даже если его удалят из базы.
  Пока копию не правили, правки администратора до неё доходят (заметка правкой не считается).
- API: `GET /lexemes` (поиск по слову и переводу, фильтры тип/уровень/категория, отметка «уже в словаре»),
  `GET /lexemes/{id}`, `GET /categories`; `GET/POST/PUT/DELETE /my-words`, `POST /my-words/import`;
  админка `POST/PUT/DELETE /admin/lexemes`, `POST /admin/lexemes/import`, `POST/PUT/DELETE /admin/categories`.
- Импорт CSV: разделитель `;`, `,` или табуляция определяется сам, заголовки по-русски или по-английски,
  несколько переводов через `|`, отчёт по строкам. В личный словарь строка без перевода берётся из общей базы.
- Стартовый набор: 12 категорий и 149 слов, фраз, идиом и фразовых глаголов A1–B2 с транскрипцией и примерами
  (`Seed/starter-lexemes.csv`, составлен для проекта). Загружается при старте только в пустую базу.
- События `UserWordAdded` / `UserWordDeleted` в Contracts — для карточек повторения на этапе 4.
- Фронтенд: `/dictionary` (вкладки «Мои слова» и «Общая база», поиск, фильтры), карточка слова базы,
  своё слово и правка, импорт с примером файла; админка: `/admin/lexemes` (список, форма, импорт с обновлением),
  `/admin/categories`. Произношение: аудио по ссылке, иначе синтезатор речи браузера.
- Тесты: 26 unit-тестов (CSV, разбор значений, нормализация, синхронизация копий), 4 интеграционных сценария
  (база и поиск, личный словарь и изоляция пользователей, импорт, админка). Всего в решении 86 тестов, фронтенд — 26.
- Проверено вживую на копии API с базой `english_platform_tests`, скриншоты телефона и десктопа в обеих темах.

Доработки после первого реального импорта (24.11.2026):
- У слов личного словаря свои уровень и часть речи (миграция `UserWordLevel` переносит их у слов из базы).

- Фильтр «Без уровня», выбор нескольких слов и уровень (в админке и категория) сразу для всех: `PUT /my-words/bulk`,

- Проверено на копии реальных 253 слов в тестовой базе: 242 добавлены в базу, 10 привязаны к уже существующим,

## Этап 4. Повторение и занятия

Сделано (26.11.2026):
- **SpacedRepetition** (схема `spaced_repetition`): карточки `review_cards` (узнавание и вспоминание, состояние FSRS)
  и журнал `review_logs` (только дописывается). FSRS-5 написан в проекте (`FsrsScheduler`), сверен с формулами
  py-fsrs тестами; шаги заучивания 1 и 10 минут, переучивания — 10 минут, желаемое удержание 0,9
  (`SpacedRepetition:DesiredRetention`). Карточка вспоминания открывается, когда узнавание впервые выучено.
  Карточки создаются по событию `UserWordAdded` и досоздаются при сборке очереди для старых слов.
- **Exercises** (схема `exercises`): задания — знакомство, выбор перевода, на слух, ввод слова, пропуск в предложении
  из примера (слово ищется и в другой форме: bumped into). Проверка без ИИ: нормализация, sb/sth, «to» необязательно,
  опечатки (Левенштейн), артикль, форма слова; объяснение по шаблону; тег ошибки для этапа 5. Журнал
  `exercise_attempts` со снимком задания (jsonb).
- **LearningSessions** (схема `learning_sessions`): очередь дня — повторения (самые «забываемые» первыми), затем новые
  слова в пределах дневного лимита из профиля, день — по часовому поясу пользователя. Оценка FSRS выводится из ответа:
  неверно — Again, почти/подсказка — Hard, верно — Good, быстро — Easy (пороги `LearningSessions:*`; новому слову при
  первом показе Easy не ставится). Ошибочное и «короткое» слово возвращается в то же занятие (до 2 раз).
  Ответ идемпотентен по `attemptId`; устаревшее задание — 409.
- API: `GET /learning/today`, `POST /sessions`, `GET /sessions/{id}/next`, `POST /sessions/{id}/answers`,
  `POST /sessions/{id}/finish`, `GET /sessions`.
- Фронтенд: `/learn` — экран занятия (прогресс, крупные варианты, клавиши 1–4 и Enter, автоозвучка, подсказка,
  «Не знаю», разбор с «повторим через …», итог), на главной — план дня. Повтор отправки при обрыве связи.
- Тесты: 45 unit (FSRS, проверка, поиск слова в примере, оценка, начало дня) и 2 интеграционных сценария занятия.
  Всего в решении 164 теста, фронтенд — 44. Проверено вживую на копии API, скриншоты телефона и десктопа.

Не сделано:
- Подбор личных весов FSRS по журналу (нужна накопленная история).
- Ограничение «не больше N минут» и выбор типа занятия (только новые / только повторение) — по желанию.

## Этап 5. Ошибки и адаптация

Сделано (26.11.2026):
- **Grammar** (схема `grammar`): темы `grammar_topics` (правило коротко, подробно, примеры с пометкой «так нельзя»)
  и справочник `error_tags` (тип ошибки → тема). Стартово 6 тем: артикли, формы слова, написание, предлоги после слов,
  -ing или to, условные предложения. API: `GET /grammar/topics`, `GET /grammar/topics/{slug}`, `GET /grammar/error-tags`;
  админка `POST/PUT/DELETE /admin/grammar-topics`, `PUT /admin/error-tags/{code}`.
- **Analytics** (схема `analytics`): `error_stats` — счётчики ответов и ошибок по типу ошибки, формату задания и слову,
  обновляются событием `AnswerChecked` из занятия. `GET /stats/weak-spots` — слабые места с правилами.
  Проблемное слово: не меньше 2 неудач, не меньше трети ответов неудачные, ошибка за последние 30 дней (`Analytics:*`).
- **Проверка**: новый тег «не тот предлог» (depend of вместо depend on).
- **Очередь**: проблемные слова (по Analytics или забытые ≥ 2 раз, `SpacedRepetition:ProblemLapses`) идут первыми.
- **Разминка**: проблемное слово сначала в лёгком формате — напоминание слова (узнавание) или выбор английского слова
  из вариантов (вспоминание, новый формат ChooseWord), без влияния на FSRS; затем обычное задание.
- **Форматы по слабым местам** (после 20 ответов): часто ошибается в формах и предлогах — больше пропусков в предложениях;
  много опечаток — больше чистого ввода; на слух заметно хуже — больше заданий на слух.
- **Работа над ошибками**: `POST /sessions {kind: "Mistakes"}` — занятие только из проблемных слов, независимо от срока.
- Разбор ответа показывает правило темы для опечаток, артиклей, форм слова и предлогов.
- Фронтенд: на экране занятия — блок «Работа над ошибками» со слабыми местами и кнопкой «Разобрать ошибки»,
  разминка и «трудное слово» в заданиях, правило в разборе; страницы `/grammar` и `/grammar/:slug`;
  админка `/admin/grammar` (темы и привязка типов ошибок к темам).
- Тесты: всего в решении 176, фронтенд — 44. Проверено вживую: правило к ошибке в предлоге и опечатке, слабые места,
  разминка в «работе над ошибками», страница правила, админка.

## Этап 6. Уровень и план

Сделано (26.11.2026):
- **LearningProfiles** (схема `learning_profiles`): банк вопросов `placement_questions`, попытки `placement_attempts`
  (ответы и текущий вопрос в jsonb), уровни `skill_levels` (навык → CEFR, источник, дата).
- **Адаптивный тест «лесенкой»**: 7 вопросов по лексике, 7 по грамматике, 4 по чтению; верный ответ — следующий
  вопрос уровнем выше, неверный — ниже; старт с A2, следующий навык — с уровня на ступень ниже результата предыдущего.
  Уровень навыка — самый высокий, где верно хотя бы раз и не меньше чем в половине ответов; общий — среднее с округлением
  вниз. Тесты проверяют, что алгоритм находит истинный уровень для A1…C2. Варианты перемешиваются, правильный ответ
  клиенту не уходит, повторная отправка ответа безопасна, незавершённый тест продолжается в течение суток.
- **Стартовый банк**: 48 вопросов (лексика и грамматика — по 3 на уровень, чтение — по 2 текста на уровень), составлен для проекта.
- **Начальный план**: после первого теста в словарь добавляется до 20 слов своего и следующего уровня, сначала из категорий
  под цели профиля (`Placement:StarterWords`). `GET /me/plan` — уровни по навыкам, уровни слов в работе, 2–4 темы
  грамматики своего уровня и чуть выше, дневная нагрузка, цели.
- API: `POST /placement/start`, `POST /placement/{id}/answers`, `POST /placement/{id}/finish`, `GET /me/plan`;
  админка `GET/POST /admin/placement-questions`, `GET/PUT/DELETE /admin/placement-questions/{id}`.
- Фронтенд: `/placement` (вступление, вопросы с текстом для чтения, «Не знаю», клавиши 1–6, итог по навыкам),
  `/plan` «Моя программа», приглашение пройти тест на главной, админка `/admin/placement` (фильтры, форма вопроса).
- Тесты: всего в решении 189, фронтенд — 46. Проверено вживую на новом пользователе с целями «Путешествия, Работа».

Не сделано:
- Аудирование и говорение (нужны TTS/STT и проверка речи — см. roadmap).
- Повторный тест не меняет набор слов — только уровни; «программа» пока не подстраивает дневную нагрузку сама.

## Этап 7. Статистика и выпуск

Сделано (26.11.2026):
- **Статистика** `GET /stats/summary` (Analytics собирает из SpacedRepetition, Vocabulary, Users, LearningProfiles через Contracts):
  путь слов «ещё не начаты → учу → узнаю (пассивный) → использую (активный: карточка вспоминания выучена со
  стабильностью ≥ 21 дня, `Statistics:ActiveStabilityDays`)»; серия дней и рекорд по часовому поясу пользователя
  (сегодняшний день не обрывает серию до полуночи); за 7 дней — ответы, точность, новые слова, минуты; ответы по дням
  за 30 дней; уровни по навыкам.
- **Страница `/stats`** и значок в шапке: плитки, полоса словаря по этапам (одна шкала синего, проверена на различимость
  при дальтонизме в обеих темах), график ответов по дням с подсказкой и таблицей, уровни, слабые места со ссылками на
  правила, история занятий (`GET /sessions`).
- **PWA**: манифест, иконки (обычные и maskable), свой service worker (`web/public/sw.js`): `/api` не кешируется,
  страницы — сначала сеть, без сети — оболочка; файлы с хешем — из кеша. Регистрация только в продакшен-сборке.
  Проверено в Edge: установка доступна, без сети приложение открывается.
- **Мониторинг**: продуктовые метрики `ep.users.registered`, `ep.words.added`, `ep.answers` (verdict, exercise),
  `ep.answer.duration`; панель Aspire в compose (`--profile monitoring`).
- **e2e** (`web/e2e`, Playwright с установленным Edge): регистрация → тест уровня → слова → занятие → статистика,
  на телефоне и десктопе. Проходит на продакшен-сборке.
- **Нагрузка** (`tests/load/load.mjs`): 100 виртуальных пользователей без пауз, 60 с — ~880 запросов/с, 0 ошибок,
  p95 150–220 мс, худший ответ < 1 с.
- **Выпуск**: `docs/deploy.md` — сервер, `.env`, HTTPS через Caddy, обновление и откат, резервные копии и
  восстановление, мониторинг и пороги тревог, проверка после выпуска.

Найдено нагрузкой и исправлено:
- Счётчики ошибок (Analytics) читали и сохраняли значение — одновременные ответы падали на уникальном индексе и теряли
  приращения. Теперь один атомарный `INSERT … ON CONFLICT DO UPDATE`; тест на 30 одновременных ответов.
- Пул Npgsql по умолчанию (100) равен всему `max_connections` Postgres — под нагрузкой ошибки 53300 и ответы до 60 с.
  Пул ограничен `Database:MaxPoolSize` (30): на пике запросы ждут в очереди.
- Каждое нажатие «начать», когда учить нечего, сохраняло пустое занятие (8,5 тыс. записей за минуту нагрузки).
  Теперь возвращается уже созданное сегодня пустое занятие.
- За HTTPS-прокси перед nginx API считал всех пользователей одним IP (лимит входов общий) и видел схему `http`.
  Число прокси — `ForwardedHeaders:ForwardLimit` (`FORWARD_LIMIT` в `.env`), nginx передаёт схему внешнего прокси.
- Маршрут статистики увеличил начальный бандл на 4 кБ (сборщик вынес `DecimalPipe` в общий код) — заменён округлением.

Не сделано:
- `docker compose up` не запускался — на машине разработки нет Docker. Первый запуск — по `docs/deploy.md` на сервере.
- Письма по SMTP (хвост этапа 2).
- Статистика по аудированию и говорению — их пока не оцениваем.

Сделано:
- **«Не могу слушать»** в заданиях на слух: час без аудио (переносится и на следующее занятие), текущее задание
  заменяется другим форматом по тому же слову без штрафа. `POST /sessions/{id}/mute-audio`.
- **Тест уровня переделан.** Старая «лесенка» считала уровнем самый высокий, где было хоть одно верное — одно
  угаданное на C1 давало C1 (моделирование: ученика B1 завышала в 36 % случаев, на две ступени — в 4 %).
  Теперь оценка по модели ответа с поправкой на угадывание и «Не знаю» (EAP), вопросы — на уровне текущей оценки.
  Два режима: быстрый (18 вопросов, точно в 62–90 % по уровням, ошибка на 2 ступени ≤ 2 %) и точный
  (36 вопросов, точно в 94–98 %). Банк вопросов — 96 (+48 во втором пакете, дозагружается в существующие базы).
- **Оформление:** режим (авто/светлая/тёмная) и 8 палитр (Классика, Океан, Лес, Закат, Лаванда, Роза, Графит,
  Бумага). Палитра — отдельный CSS в `public/themes/`, грузится только выбранная; применяется до старта приложения.
- **Внешний словарь.** Викисловарь (kaikki.org, CC BY-SA) по запросу: транскрипция (к виду учебных словарей),
  русские переводы по одному на значение, часть речи, примеры, начальная форма (buried → bury). Найденное
  сохраняется в общую базу с пометкой «проверить»; ответы кешируются (`vocabulary.dictionary_cache`).
  Уровни — встроенный список CEFR-J + Octanove (9 971 слово). Слова базы без транскрипции/части речи/примера
  дозаполняются при поиске.
- **«Улучшить словарь»** (`/dictionary/improve`): проверка личного словаря порциями, предложения «было → стало»
  с галочками: уровень, тип (фразовый глагол, идиома), начальная форма с переводами, транскрипция, часть речи,
  пример. На копии реального словаря (146 своих слов): 28 типов, 54 уровня, 89 транскрипций, 112 частей речи.
- **Поиск в словаре:** нет в общей базе — ищем во внешнем словаре прямо в списке.
- **Пополнение базы (админка):** фоновая загрузка слов списков CEFR выбранных уровней (до ~10 тыс.), ~2 слова/с.
- **Автопополнение:** свои новые слова закончились — занятие само добавляет слова своего уровня и следующего,
  сначала по темам целей. Отключается в профиле.
- **Практика** (`/practice`): чтение (10 текстов A1–C1 и «Свой текст»: нажал на слово — перевод, озвучка,
  «в мои слова», «+ слово» для фраз; знакомые слова подчёркнуты; «Слушать текст»), игры на своих словах —
  «Пары», «Блиц», «Собери слово». Игры не меняют расписание повторений.
- Админка «Тексты» (`/admin/reading`): список по уровням, создание, правка, скрытие, удаление. Тексты: второй пакет
  ещё 12 (по два на уровень A1–C2), всего 22; дозагружается в существующие базы один раз.
- Слова из текстов и словаря — полноценные: уровень всегда (вне списков CEFR — C1), пример с русским переводом
  из Tatoeba (CC BY 2.0 FR, кешируется), дозаполнение пустых полей доходит до «Моих слов» (если слово не правили).
  Словарь не ответил — так и пишем («Повторить»), а не «не нашли»; таймаут 20 с.
- Прогресс каждого слова: `GET /my-words/progress` (этап новое/учу/узнаю/использую, ответы, забывания, следующее
  повторение) — значок в списке «Мои слова», блок «Прогресс» на странице слова.
- Название **Owlish**: шапка, заголовок, PWA-манифест, сова в логотипе и иконках приложения, Owlish API.
- Иконка приложения — из `web/public/icons/icon.png` (дизайн пользователя): из неё собраны favicon, логотип в шапке, иконки PWA (обычные, maskable, apple-touch).
- **Английский интерфейс**: «Язык интерфейса» в профиле теперь работает, переключение без перезагрузки. Словарь `core/i18n/en.ts` (~800 строк интерфейса и сообщений сервера) грузится отдельным чанком только для английского. Учебный материал (переводы слов, объяснения правил) остаётся русским. См. decisions.md §15.
- **Питомцы** (вкладка «Питомец», модуль Pets): котик, корги, хомяк с окрасами; знакомство (вид, окрас, имя), комната с окном (день/ночь), сытость, настроение, уровни и рост (малыш → подросток → взрослый), угощения за занятия, кормление, мячик, «погладить», гардероб (бантик, шарф, очки, колпачок, корона — по уровням), реплики со словами из словаря. Без занятий голодает, через 2 дня грустит, через 5 «уходит гулять», возвращается после занятия. Питомец гуляет по страницам (левое поле на широком экране, угол на телефоне), радуется верным ответам в занятии. Витрина рисунков — /pet/lab. См. decisions.md §16.
- Питомец как мотивация учиться: **просьбы дня** (занятие; игра «Пары»/«Блиц»/«Собери слово»; текст, новые слова, вопросы питомца или работа над ошибками) со ссылками и наградой угощениями; «Покормить» без угощений подсказывает, какими делами их заработать, сытый питомец зовёт к делу; «Поиграть» стало вопросами о словах из словаря; **обстановка комнаты — достижения** (11 вещей за занятия, слова, серию дней, тексты, игры, ответы питомцу); серия дней по часовому поясу пользователя; кнопка «Я дочитал(а)» в текстах; питомец на страницах сам напоминает слова, просьбы и занятие.
- Общая база без повторов: одно слово — одна запись (части речи склеены в переводы), уникальный индекс по слову; миграция склеила 131 повтор. См. decisions.md §17.
- «Поддержать проект»: страница /support (история, что сделано вместе, на что пойдут деньги, цель сбора, CloudTips и Boosty), ссылка внизу страниц, карточка в профиле, приглашение после 3-го и каждого 10-го занятия; «Я поддержал(а)» на доверии даёт значок в профиле и сердечко питомцу. Ссылки и цель — в настройках сервера, раздел Support.
- Всплывающие сообщения (sonner) грузятся отложенно (@defer): стартовый бандл 500 → 465 КБ.
- Начальная загрузка снова 495 кБ: иконки шапки и уведомлений — свои копии, пакет lucide больше не попадает в main.

## Окружение разработчика

- .NET 10 SDK и Node 24 установлены портативно: `%LOCALAPPDATA%\Programs\dotnet10`
  и `%LOCALAPPDATA%\Programs\node-v24.22.3-win-x64`; глобальный dotnet не изменён.
- Visual Studio 2026 поставила системный .NET SDK 11; `global.json` разрешает его (`rollForward: latestMajor`),
  проекты остаются на `net10.0`.
- PostgreSQL 16 локально, пользователь `postgres`; база приложения `english_platform`.
  Интеграционные тесты: `TEST_DATABASE_CONNECTION` на отдельную базу `english_platform_tests` (тесты её перезаписывают).
- Фронтенд: `npm start` в `web/` (Node 24 через nvm), API на http://localhost:5080. Администратор в Development
  появится, если задать `Identity:AdminEmail` и `Identity:AdminPassword` (например, через user-secrets).
- Сборка: `dotnet build EnglishPlatform.slnx -m:1`; тесты: `dotnet test --solution EnglishPlatform.slnx`.
- После переноса папки проекта удалить `bin` и `obj`: в них остаются старые пути NuGet.
